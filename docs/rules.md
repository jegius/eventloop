# Правила разработки

## Общие принципы

- **Язык кода и комментариев**: комментарии и документация — на русском языке.
- **TypeScript**: весь новый код фронтенда — на TypeScript.
- **SOLID**: придерживаемся принципов SOLID.
- **Паттерны**: Repository/Service для бизнес-логики.
- **Логирование**: все логи проходят через стандартный модуль `logger`.

---

## Rust (интерпретатор)

- Стиль кода: `rustfmt` (стандартный формат Rust).
- Ошибки: использовать `Result<T, E>` и `thiserror` для типизированных ошибок.
- Безопасность: избегать `unsafe` (кроме необходимых WASM-границ).
- Модульность: каждый модуль отвечает за одну задачу.
- Тесты: юнит-тесты в каждом модуле (`#[cfg(test)]`).

### Структура модуля

```rust
// Пример структуры модуля
pub struct Lexer { /* ... */ }

impl Lexer {

```

---

## TypeScript (фронтенд)

- Строгая типизация: `strict: true` в `tsconfig.json`.
- Компоненты: Web Components (Custom Elements + Shadow DOM).
- Стили: CSS в Shadow DOM (изолированность).
- События: Custom Events для коммуникации между компонентами.
- Состояние: простой стейт-менеджмент (без тяжёлых библиотек).

---

## Git

- Ветки: `feature/...`, `fix/...`, `docs/...`.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`).
- Перед коммитом: прогон тестов и линтеров.

## Проверка качества

- `cargo fmt` — форматирование Rust.
- `cargo clippy` — линтер Rust.
- `cargo test` — тесты Rust.
- `npm run lint` — линтер TypeScript.
- `npm run test` — тесты TypeScript.
